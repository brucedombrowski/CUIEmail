# SendCUIEmail

Encrypt files for email transmission of Controlled Unclassified Information (CUI) when S/MIME certificate exchange is not practical. Sender runs one script. Recipient decrypts with built-in PowerShell, no software to install.

Built for constrained Windows 11 environments (CIS, DISA STIG, Microsoft Security Baseline). Also runs on PowerShell 7 on macOS and Linux for development and testing.

## Quick Start (Sender)

1. Double-click `Encrypt.bat`, or drag files onto it.
2. Enter a password, or press Enter for a generated passphrase.
3. Select the CUI category.

Output goes to a timestamped folder next to the source files:

| File | Purpose |
|------|---------|
| `*.Locked` | Encrypted files, original extension preserved |
| `Decrypt_Instructions.html` | Recipient instructions with a paste-and-run decryption one-liner |
| `CUI_Email_*.msg` | Pre-formatted Outlook draft with attachments and CUI markings (Windows with Outlook only) |
| `Password_Email_*.msg` | Separate draft for password delivery over an approved channel |

Send the password out-of-band: phone, SMS, in person, or S/MIME. Never in the same email, and never in unencrypted email. See NIST SP 800-63B §5.1.3 and NIST SP 800-171 §3.13.8.

## Recipient

Open `Decrypt_Instructions.html` and paste the one-liner into PowerShell, or run `Decrypt.bat` from this repo. Enter the password. The decrypted file appears next to the `.Locked` file.

## Cryptography

| Parameter | Value | Standard |
|-----------|-------|----------|
| Cipher | AES-256-CBC, PKCS7 padding | FIPS 197, NIST SP 800-38A |
| Integrity | HMAC-SHA256 over header and ciphertext, encrypt-then-MAC, verified before decryption | FIPS 198-1 |
| Key derivation | PBKDF2-HMAC-SHA256, 600,000 iterations, 64 bytes split into AES key and MAC key | NIST SP 800-132 |
| Salt and IV | 128-bit random, unique per file | NIST SP 800-90A |
| Library | .NET `System.Security.Cryptography` only, no third-party code | FIPS 140-2 via Windows CNG when FIPS mode is enabled |

File format v2: `"SCUI"` `0x02` `[4-byte iterations]` `[16-byte salt]` `[16-byte IV]` `[ciphertext]` `[32-byte HMAC tag]`. Defined once in `Crypto.psm1`, which Encrypt, Decrypt, the tests, and the recipient one-liner all share.

Wrong password or a modified file fails verification and no output file is written. Version-1 files (`[salt][IV][ciphertext]`, no tag) from earlier releases still decrypt, with a warning. See [issue #2](https://github.com/brucedombrowski/SendCUIEmail/issues/2).

## Compliance Documents

| Directory | Contents |
|-----------|----------|
| `Requirements/` | REQ-2026-001 cryptographic compliance requirements. JSON is the source of truth; LaTeX and PDF are generated by `build-requirements-pdf.py` |
| `Verifications/` | VER-2026-001 maps each requirement to code and test evidence |
| `Decisions/` | Decision memoranda (DM-2026-001 through 007): cross-platform support, 10 MB size limit, password transmission, CUI categories, and others |

Standards applied: FIPS 140-2, FIPS 197, NIST SP 800-132, NIST SP 800-38A, NIST SP 800-90A, NIST SP 800-63B, NIST SP 800-171, 32 CFR Part 2002.

## Testing

```powershell
.\Test.bat            # Windows
```

```bash
./test.sh             # macOS/Linux, requires pwsh
```

`Test.ps1` exercises the shared module: round trips (empty, single block, multi-block, binary, 100 KB), 300 wrong-password attempts with zero false accepts, bit flips in every header field, ciphertext, and tag, truncation, header-carried iteration counts, and legacy v1 decryption. `test.sh` also runs the non-interactive integration path and updates the VER document.

## Limits

Maximum attachment size is 10 MB (DM-2026-002). Larger files need a different transfer method.
