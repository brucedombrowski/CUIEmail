\dmsection{Purpose}

This memorandum documents a readiness assessment for beta testing of SendCUIEmail v0.5.2 with users who have limited technical capability but knowledge of CUI handling requirements.

\dmsection{Target Audience Profile}

\textbf{Beta Tester Characteristics:}
\begin{itemize}
    \item Familiar with CUI marking requirements (32 CFR Part 2002)
    \item Understands need for encryption when transmitting CUI via email
    \item Limited command-line experience
    \item Comfortable with Windows desktop applications
    \item May not know what ``PowerShell'' is
\end{itemize}

\dmsection{Identified Concerns}

\textbf{High Priority:}
\begin{enumerate}
    \item \textbf{Output Location Confusion} -- Files are created in a timestamped subdirectory of the current working directory. Non-technical users may not understand where ``current directory'' is.

    \item \textbf{Password Entry UX} -- Console password prompts show no characters while typing (security feature). Users may think nothing is happening.

    \item \textbf{Recipient File Path Handling} -- Recipients need to navigate to where they saved the .Locked files. No drag-and-drop support.
\end{enumerate}

\textbf{Medium Priority:}
\begin{enumerate}
    \item \textbf{No Quick-Start Guide} -- Users would benefit from a 1-page PDF with screenshots.

    \item \textbf{``What is PowerShell?''} -- Some users have never seen a PowerShell window.

    \item \textbf{Weak Password Acceptance} -- Tool accepts ``12345678'' (meets 8-char minimum but is trivially guessable).
\end{enumerate}

% ----------------------------------------------------------------------------
\dmsection{Assessment Summary}

\begin{center}
\Large\textbf{CONDITIONALLY READY FOR BETA}
\end{center}

\textbf{Rationale:} Core functionality is complete and tested. The tool correctly encrypts files using FIPS-compliant algorithms, generates proper CUI markings, and provides compliance guidance. However, some UX friction exists for non-technical users.

\textbf{Recommended for Beta With:}
\begin{itemize}
    \item Brief verbal walkthrough or screen share for first-time users
    \item Technical support contact available during initial testing
    \item Feedback collection on specific pain points
\end{itemize}

\textbf{Not Recommended Without:}
\begin{itemize}
    \item Some form of user orientation (even informal)
    \item Expectation setting that this is command-line based
\end{itemize}

% ----------------------------------------------------------------------------
\dmsection{Recommendations Before Wider Release}

\begin{enumerate}
    \item Create a 1-page Quick-Start Guide (PDF with screenshots)
    \item Add note about password entry: ``Characters will not appear as you type''
    \item Consider adding output path to final summary (full path, not just folder name)
    \item Document the ``where are my files?'' answer prominently
\end{enumerate}

\dmsection{Implementation Plan (v0.5.3)}

The following improvements will be implemented before developer beta testing:

\subsection*{Priority 1: Password Entry Hint}

\textbf{Problem:} SecureString input shows no characters; users think nothing is happening.

\textbf{Solution:} Add hint line before each password prompt:
\begin{verbatim}
(Characters will not appear as you type)
Enter encryption password:
\end{verbatim}

\textbf{Files Modified:}
\begin{itemize}
    \item \texttt{Encrypt.ps1} -- Get-SecurePassword function (2 prompts)
    \item \texttt{Decrypt.ps1} -- Get-Password function (1 prompt)
\end{itemize}

\subsection*{Priority 2: Output Location Clarity}

\textbf{Problem:} Output folder shown in gray at bottom, easy to miss.

\textbf{Solution:} Move output folder to top of file list with yellow label and full paths:
\begin{verbatim}
Output folder:
  C:\Users\Dev\Documents\SendCUIEmail_20260121_143022

Files ready to send:
  C:\Users\Dev\Documents\SendCUIEmail_20260121_143022\Document.pdf.Locked
  C:\Users\Dev\Documents\SendCUIEmail_20260121_143022\README.md
\end{verbatim}

\textbf{Files Modified:}
\begin{itemize}
    \item \texttt{Encrypt.ps1} -- Final summary section
    \item \texttt{Decrypt.ps1} -- Final summary section
\end{itemize}

\subsection*{Deferred Items}

\begin{itemize}
    \item \textbf{Weak Password Warning} -- Deferred for developer beta; add if feedback indicates need
    \item \textbf{Quick-Start Guide PDF} -- Deferred until non-technical user release
\end{itemize}

\subsection*{Success Threshold}

\begin{itemize}
    \item \textbf{Pass:} All 8 Required criteria pass, and at least 4 of 5 UX criteria pass
    \item \textbf{Conditional Pass:} All Required pass, but UX feedback requires minor changes
    \item \textbf{Fail:} Any Required criterion fails
\end{itemize}

\subsection*{Post-Beta Actions}

\textbf{If Pass:}
\begin{enumerate}
    \item Proceed to non-technical user preparation
    \item Create Quick-Start Guide PDF
    \item Release v1.0.0 (production-ready for non-technical CUI handlers)
\end{enumerate}

\textbf{If Conditional Pass:}
\begin{enumerate}
    \item Address UX feedback in patch release (v0.5.4)
    \item Re-test affected areas
    \item Then proceed to non-technical preparation
\end{enumerate}

\textbf{If Fail:}
\begin{enumerate}
    \item Document failure details
    \item Fix blocking issues
    \item Re-run beta test
\end{enumerate}
